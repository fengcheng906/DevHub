# Git 亲手实操路线图（第一次自己提交）

> 背景：到目前为止，仓库的 2 次提交都是助手代做的。从下次开始，**commit 和 push 由你亲手完成**——这是程序员的日常动作，练 3 次就成肌肉记忆。
> 前提：Git Bash 已打开，且你 `cd /c/DevHub` 进了仓库。

## 每次存档的固定三步（背下来）

```bash
git add -A
git commit -m "写清楚这次改了什么"
git push
```

## 三步各自的意思

1. **`git add -A`** —— 打包
   把所有新增/修改的文件放进"待存档清单"。`-A` 表示全部。
2. **`git commit -m "说明"`** —— 存档
   把清单里的内容正式记一笔账。`-m` 后面的引号里写这次改动的说明，给未来的自己看。
   好的说明例子："完成重命名助手 v0.1"、"修复中文文件名乱码问题"。
3. **`git push`** —— 上传
   把存档同步到 GitHub。做完这步，github.com/fengcheng906/DevHub 上就能看到。

## 常用查看命令（随时用）

| 命令 | 作用 |
|---|---|
| `git status` | 看哪些文件改了还没存档（最常用，放心随便敲） |
| `git log --oneline` | 看历史存档记录（一行一条） |
| `git diff` | 看具体改了哪几行 |

## 你第一次实操的任务（练习时完成）

1. 在 `02_Learning/day1` 里随便创建一个文件（正好用你练过的 `echo` 命令）

4. 打开 github.com/fengcheng906/DevHub 刷新，亲眼看到自己的文件在线上

## 常见问题

- **push 卡住没反应**：可能在等你在浏览器里完成 GitHub 登录授权，切到浏览器看一眼
- **`nothing to commit`**：说明没有改动可存档，正常现象
- **手滑 commit 说明写错了**：不用慌，下次写对就行，新手阶段不学改历史
